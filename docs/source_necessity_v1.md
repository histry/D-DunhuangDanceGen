# A2-V3 Candidate Support / G2-M Source Necessity

基线c7257d2冻结。新实现仅位于research/necessity及对应scripts/config/tests；正式Planner、EDGE、旧A2-V2、原G2权重/判决、Native31不改。本轮不增加编码器、Transformer、RootNet、生成主干或SQP。

## 工作包A：先做新任务支持域与纯算子比较

使用已封存且由原始音频/动作独立重建通过的9,199窗，读取前核对公开SHA与原始重建回执；新Test张量不读。五类干扰变量拼为45D：事件数2、时间分位数32、直方图8、log能量2、onset1。均值、标准差、相关协方差仅拟合Train，shrinkage=0.1。

新任务名不复用旧V2资格：
- time：同歌同编舞的真实时段区分，负例音频起点至少差60帧。目标只是官方源时钟位置，不称艺术不协调；绝对时钟只用于标签/构造，不输入算子评分。
- association：同实际起点、不同已知音乐/编舞关联。每查询按固定SHA选择最多3个供体曲目、每曲目最多16个真实窗，Train/Val采用相同供体预算；允许弃权。

Train最近供体距离的90%分位数为主匹配半径，Train白化径向范数99%分位数为共同支持上限；Val不校准。两任务各自校准，超出支持域或无供体即弃权。不是放宽旧W1等门限，旧106/0结果原样保留。

资格与旧要求同量级：每角色至少30查询、15录制，Train至少3个曲目组、Val至少2组。不充分不报R1/MRR。本轮只运行已有strict one-to-one partial path的相对事件时钟算子、Train组均衡的6D干扰变量线性基线、内容置零控制；不训练SDMR，不进行30/15Hz编码器比较。

选择器比较联合的完整配对干扰统计，不能把这个距离用于评分，否则正确配对与自身的零距离会泄漏标签。评分只接收音乐查询侧和动作候选侧的统计/相对事件时钟，不读取查询的目标动作统计。候选在所有算子之间固定；报告覆盖、来源组均衡R1/MRR及1000次整曲目组bootstrap（已知曲目ID/开发数据范围，不能当新盲测）。

## 工作包B：任务资格与允许的开发机制训练

本方案明确允许在已曝光开发数据上检验机制。这里新建独立的G2-M开发研究任务；不把Data V3通用ready_for_new_training改成true，也不认证未知作品别名/预训练曝光，更不授予正式泛化或生成资格。

从Data V3新Train/Val的真实151D/Jukebox窗口建立：
- 训练真值始终是当前录制自身的精确姿态与音乐；参考条件也来自该录制。不同录制的姿态不被混成逐帧同姿态真值。
- 验证A/B必须不同原始录制、同官方basic编舞、同原音频/起点，Jukebox实际张量精确相等；观测上身平均SO(3)差至少0.05rad，避免对不可区分来源强加判别。
- 每个原始SMPL先完整解码/求导，再选择150帧窗口。实际运动阶段由已有upper8速度峰/启动/方向转折/定格代理给出，Root转向不作为上身监督。
- 扩展mask为实际阶段中心±2帧与原稀疏键的并集，仅保留completion_upper8真实可见帧，至少6个阶段帧；不读40个隐藏帧作为条件、不新增Root/接触/手腕标签。
- 核对原始SHA、来源时钟、完整目标、冻结EDGE Scaler、真实layer66/30fps Jukebox和无补齐回执。新Test只读角色身份元数据。

资格至少30个Train窗口、15个Train录制、3首Train音乐；Val至少4首音乐、8个录制。四个固定验证音乐/来源对只依照数据资格和SHA选择，模型运行前冻结。作品别名与预训练曝光UNKNOWN在任务及权重中保留。资格不足则自动停止训练，不通过改种子、阈值或抽样来补齐。

## 因子预算

所有组同EventMusicAdapter Cross架构、同初始化、同Data V3 Train人口、同音乐与高斯噪声、同400更新/batch2、lr1e-4、梯度裁剪1。保留原MSE+0.1速度+0.02旋转+0.05来源重构，SO(3)跟随权重2。

|组|专门跟随监督|时间步|
|---|---|---|
|M0|原稀疏键预算至多3帧|50–949|
|M1|真实可见运动阶段|50–949|
|M2|原稀疏键|实际50步DDIM支持|
|M3|真实可见运动阶段|实际50步DDIM支持|
|M3_shuffle|同M3，来源关联置乱|同M3|

M0是在同一新任务上重训的匹配对照，历史冻结G2-2另行保留，不把不同训练人口的旧权重混作同预算M0。主预算总计2,000更新，固定最后一步，不按Val选权重。时间步采用相同Uniform分位数：旧映射50+floor(900u)，新映射到升序实际DDIM时刻19/39/…/999；因此检验的是实际支持及其分布，不能单独归因成仅覆盖范围。高斯噪声另以相同步种子生成，所有组一致。

置乱通过精确匹配保持来源出现次数不变，禁止相同音乐组、编舞与录制配对；目标及标签仍为原自身真值。没有把110帧硬贴到输出；扩展只作用于训练损失。

## 评估、重放与NULL代数

四首固定Val音乐，每首一个预注册种子。每例运行bypass（observed NULL严格等价）、五权重各A/B、稀疏硬键A/B，共52次150帧采样和原Native。分别按A/B真参考评价全窗、提供帧、隐藏帧、关键帧及阶段，保存活动度、连续指标、原双向偏好。原门槛不改：两方向均>.001rad、相对bypass收益>0、活动度>=.9。来源对和候选人口改变，M0与M3的因果对照只在本轮同人口内解释，不能把它们与历史0/4当同人口提升。

当前observed策略将全缺失参考残差强制为零，所以Delta(E,M)-Delta(NULL,M)=Delta(E,M)。测试将输出权重设为非零后核对恒等式；运行时对初始化和五组权重分别保存证书。该“中心化”在现有合同中没有新增作用，不增加冗余分支。来源差异损失等后续改造需另行注册，不同时叠加到本轮两因素。

先push GitHub，服务器精确拉取提交，再用新目录：

    tmux new-session -d -s ddg-source-necessity 'bash scripts/run_source_necessity.sh outputs/source_necessity_01 outputs/source_necessity_01_receipt > outputs/source_necessity_01.log 2>&1'

顺序为完整回归、EDGE补充、A2新支持域主运行/新进程重算、G2任务原始来源预检/新进程重建、通过才训练/生成，再独立加载冻结末步模型重生成。重放禁止优化器，逐值比较来源mask、训练人口、时刻/置乱计划、指标、normalized/native/FK和Native结果。结束确认exit_status=0后另运行export_source_necessity.py --seal，绑定执行提交、输入/模型SHA和回执。

旧src/config全部保持不变由seal核对。原始资产、身份、权重留服务器，公开仅聚合统计与哈希。所有失败目录保留，SSH只清理本轮临时辅助文件。即使机制研究改善，正式检索/生成与G3仍不能跳过独立评价和物理资格。
