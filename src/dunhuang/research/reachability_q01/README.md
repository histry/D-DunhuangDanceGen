# Reachability-Q01

本轮结束单槽位Joint优于完整顺序枚举的假设。新增共享纯函数 `planning/anchor_reachability.py`，仅作为可调用合同，不自动接入正式Planner。实际首末帧中心是[a,b−1]和[0,T−1]，区别于旧四节点整数域的[a,b]/[A,B]合同。

A先验证已有9任务：有理数闭式可达区间、5项排除和4项既有合法执行见证；先交付实际冻结动作加证书观看页。B/C在浏览器验收后，完整登记139个既有R47单位，依时间顺序选择完整证据支持的Upper Onset、Upper Peak、Body Low-run End；缺失不替换。三种有限音乐事件对应假设先固定目标身份，再计算联合时间窗口可行性。构造的PL速率见证不保证4帧保护、特定插值光滑性、G1或艺术质量；实际新Core另行G1装配与原门筛查。

`single`和`multiple`使用有理数，返回rate_status以及额外约束未知状态。多锚点必须联合传播，不能将独立边际区间相交当作充分条件。160个预登记随机例用独立LP验证；这验证数学实现，不是新的音乐对应准确率。

先推GitHub，服务器tmux运行 `PYTHONPATH=src python -m dunhuang.research.reachability_q01.study preview`；真实观看验收绑定manifest后运行 `study controls`，再用新进程 `study replay` 精确复验。B/C观看 `python -m dunhuang.research.reachability_q01.view`。未改变旧E1-W、GTW、Q02、G1或来源目录，不训练网络，BAS／SDMR不选路。

在缺乏独立音乐—动作事件对应证据时，C仅为技术可控性人口审查，不能说哪个假设更好；不自动进入D整曲实验，语义与艺术质量保留UNKNOWN／NOT_EVALUABLE。
