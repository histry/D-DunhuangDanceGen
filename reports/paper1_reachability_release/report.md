## A：实际帧中心合同的精确证书

新增可独立调用的纯函数 `src/dunhuang/planning/anchor_reachability.py`，没有自动接入正式Planner。复用旧 `feasible_time_map.py` 的输入校验；旧四节点整数域使用另一套端点／安全半径定义，本轮未直接套用其长度公式。

本轮实际来源帧中心是 `[a,b−1]`，目标帧中心为 `[0,T−1]`。给定来源锚点s，设 `L=s−a`、`R=b−1−s`、`D=T−1`，源到目标局部倍率为 `l=0.75`、`u=1.33`，则：

```
t_min = max(l*L, D-u*R)
t_max = min(u*L, D-l*R)
minimum_error = distance(requested_target, [t_min,t_max])
```

同时必须满足总时长 `l*(b−1−a) ≤ D ≤ u*(b−1−a)`。仅有端点、单调性和速率条件时，区间是精确的；区间内任一点可由经过锚点的分段线性时钟实现。代码对声明的十进制参数使用有理数算术，输出浮点读数及分子／分母，避免将接近边界的浮点误差当成严格排除。

输入非法（NaN、布尔帧、源锚点越界、颠倒速率、少于两个真实帧中心）报错。总时长无解时区间及误差下界为NULL，不填假数。`rate_status`只说明本速率合同；存在尚未检查的插值族、保护边缘、运动支持或G1时，顶层状态为 `UNKNOWN_WITH_ADDITIONAL_CONSTRAINTS`。这不是最终执行合格证。

## 多锚点：边际可达不等于同时可达

`multiple`以有理数区间在有序来源节点上前向／后向传播，约束相邻节点目标增量在 `[l*Δs,u*Δs]` 内，并与登记目标窗口相交；端点固定，重复来源坐标的窗口相交，绝不移动节点制造解。可选固定节点可表达额外时钟保护。仅当整条链可行才返回分段线性数学见证，仍不认证G1或特定光滑参数化。

一个代码测试的反例：来源[0,100]、目标[0,100]，s=40→t=40与s=60→t=70分别都可达，但相邻20来源帧要求30目标帧，超过1.33，不能同时成立。

25项合同测试包含160个预登记随机数学案例：80个单锚点区间用独立LP分别求下／上界，80个多锚点链用独立LP检查可行性，总240次LP优化调用。所有对照通过。它们验证实现，不是音乐对应准确率，也不是新的算法性能样本。
