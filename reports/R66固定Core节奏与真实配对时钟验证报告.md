# R66 固定 Core 内部节奏与真实配对时钟验证报告

日期：2026-11-20。科学代码：`a5c325f3a71485b85d6a332ddd89e66621f5fcdb`，基于 R65 `c6d4049`；先发布 GitHub，再同步服务器用 tmux 执行。正式 Fixed48 与冻结 E1-W、R64/R65 输出和准入标准未改变。

## 结论

已交付真实 ChangE 单 Core 的三栏观看页：相同来源区间、相同音乐区间、相同240帧，分别为 Uniform、原 E1-W、实验性 Rhythm Warp。主候选观看包先回传并验收，再运行 ShuffledRhythm。新方法能够产生部分非均匀合法映射，但没有建立独立音乐质量收益，不能升级 Planner。

R66-A 的真实配对时钟诊断也没有证明当前 R64 速度峰—拍点/重音代理稳定偏好真实录制时钟。R66-B 的目标得分上涨不能代替质量评价。

## R66-B：固定240帧内部映射

冻结12个展示位置、8个独特来源区间、3首已曝光敦煌音乐；4个位置是同一来源换音乐，不是12条独立录制。来源身份和顺序均取自冻结 R64 Fixed48，未重新搜索事件或按结果换样本。运行前核验原 E1-W 时间图及12条实际重采样旋转哈希与父输出相等。

B0为显式匀速重定时（不冒充原速）；B1精确复用原 E1-W；B2为有限 beam 的 PCHIP source-to-target 映射，最多8个真实阶段代理锚点；B3用同一算法和预算，将 Core 内的音乐代理事件平移120帧后取模，实际播放音乐不变。B3只是反事实代理控制，不是艺术错误标签。

端点和240个目标帧固定，原来源顺序、来源支持不变。所有 PCHIP 段经解析导数极值与密网检查，dtarget/dsource 始终在[0.75,1.33]；实际 source positions 用曲线数值反解。映射为C1，不保证C2。目标固定为0.5拍点+0.5重音，减去各0.05的规范化速度偏差与曲率代价，未根据本轮结果调整。

主候选：Uniform 12/12、E1-W 12/12取得合法结果；Rhythm 10/12。10个合法结果中，4个选择非均匀映射，6个选择显式匀速候选；两个男冥想案例因缺乏速度峰/音频代理证据保持 NOT_EVALUABLE，没有改选容易样本。非均匀结果来自莲花两个音乐案例、女冥想一个案例和男琵琶1一个案例，不能称所有敦煌动作都学会了节奏演绎。

逐例保存实际输出的 SO(3)、身体22 FK D1/D2/D3、空间幅度、路径长度、端点速度与真实读取位置。优化所用的映射源峰与实际输出重新检测的运动峰分开。零重采样重建误差只检查实现一致性，不是学习式来源保真成绩。完整逐例标量及按来源区间的描述见 `r66_release/B_all_available_summary.json`，不以12个展示位置计算独立置信区间。

例如男琵琶1的映射代理分数从原 E1-W 的0.0416变为0.9211，但身体FK D3 Q95也从47.06变为52.79 m/s³。该例既不能仅凭目标分数判为更协调，也不能仅凭D3变大判为更差。另6个合法案例选择了匀速，不能隐藏为“统一改进”。

48帧 Transition 只保留原计划预算，本轮没有重算连接。端点姿态相同不代表端点速度/加速度相同；之前的 Bridge 合格状态不继承到新 Core。

## R66-A：真实配对时钟有效性

复用 R59 原338个登记查询，固定150帧窗内的同一120帧动作区域。运动峰从完整原录制先提取，再切区；音频从真实 WAV 重新提取，源偏移只加一次。比较真实来源时钟与非循环−15、−8、+8、+15帧读取；不补齐、不循环、不为每种偏移重新选运动峰。

| 数据人口 | Primary可评分/登记 | 正确时钟胜率，音乐组均衡 | 95%分组区间 | 五时钟R@1 |
|---|---:|---:|---:|---:|
| AIST++ Train，48组 | 266/266 | 48.44% | 43.40%–53.52% | 14.93% |
| AIST++已曝光Val，6组 | 36/36 | 49.31% | 36.11%–59.03% | 19.44% |
| FineDance Genre Train诊断，12条 | 29/36 | 57.99% | 38.19%–75.69% | 26.39% |

先窗内、再原始动作SHA、再音乐组均衡；并列给半胜与均匀首位概率，完整五条件与缺失覆盖分开。Density无信息对照的成对胜率严格为50%、首位率为20%。Primary三个分层的成对区间均跨50%，没有建立稳定的正确时钟优势。FineDance还有7个不可评分查询，并且只具备官方同ID/共同原点，不能冒充AIST级波形时钟校准。

同域同角色错歌先按音频SHA和固定哈希取3候选，再按实际共同区间RMS和局部拍间隔选择；不按模型分数挑选，也不扩大候选池。它只评价来源关联诊断，不能把错歌称为艺术错误舞蹈。完整覆盖、能量与密度基线、同查询差值及错歌读数保留在 `r66_release/A_summary.json`。

这些来源和音乐均有历史开发曝光；分组区间只是登记人口诊断，不能变成新音乐或未见编舞泛化证据。真实录制时钟也不是逐事件发力、定格或文化语义的唯一正确标签。

## 执行、交付与复验

R66-A/R66-B 主实验、错位控制与独立复验分别在 tmux 新进程运行，保留成功/失败日志和 exit_status。服务器合同测试64项通过；最终本地完整回归1091通过、9跳过、4警告。

服务器开启证书验证的 GitHub HTTPS fetch 遇到 GnuTLS 握手故障，未关闭证书验证。改用已在 GitHub 发布并由客户端核对远程SHA的公开 Git bundle；服务器校验包哈希、父提交、FETCH_HEAD 后 fast-forward。同步回执如实记录该路径。

第一次上传的 shell 启动器受 Windows 换行影响，在科学运行前失败；保留失败回执，规范为LF后执行。未改变科学算法、人口或权重。

首批8个观看文件7,660,917字节在用户明确授权后回传，逐文件核对SHA。浏览器实际检查12组切换、8秒主音乐时钟、暂停、0.5倍速、拖动及单帧，两个不可评价位置可见，无脚本错误；临时127.0.0.1只读服务在验收后关闭。观看验收不是独立艺术评价。

独立复验分别重提66份原始音频时钟、120条完整原录制运动峰；以及重做B的有限搜索、SO(3)采样、实际动态测量与观看包。逐项差异见发布目录三个 independent 文件，不能用字节复现代替科学效果证据。

## 结论边界

本轮是实际来源动作的合法时间重采样，不是神经网络创造新动作、插入新停顿或改变运动顺序。没有训练SDMR/Diffusion，没有扩大Planner或运行整曲，也没有改变门槛以取得通过。人工音乐协调、文化正确性、世界Root/接触及Native24继续 NOT_EVALUABLE，`can_route=false`。

下一步应先独立检验哪些运动节点与真实音乐时间存在可靠关系，结合实际观看反馈决定是否保留内部节奏机制。当前不宜继续调整奖励权重，或用更高的自用代理分数支撑三尺度联合规划质量结论。
