## 算法与工程修正

1. 连续 Event Plan 参考按单调源→音乐映射采样。Rot6D 先转 SO(3)，使用相对旋转指数映射插值；Root 线性、预测 contact 最近邻仅用于来源转换，实际软条件仍只观察关节 12–19。半开源区间最后不足一帧的采样显式保持最后已观测姿态。严格检查来源 SHA、时钟、速度界限和重叠条件一致性。
2. 冻结 Normalizer 越域关节帧置为未知，不裁剪物理源姿态。150 / 450 / 3601 帧已有计划的上身软参考关节帧均为 100% 支持；这不是完整 151D 支持，也不是生成质量通过。
3. Adapter 输入为参考值、观测掩码和明确源相位，零初始化残差接入同一 EDGE cond_encoder，同时影响 pooling / FiLM / cross-attention，保留原 CFG 条件丢弃。训练显式提供 source_positions/150，相位增强使用与推理相同的 SO(3) 算子；配对任务不改变真实音乐时钟。
4. 训练以 recording_uid 分组，拒绝相同来源字节跨组。先做完整支持域预检，再作来源隔离。CPU 预检不初始化 CUDA。新增真实数组的集成测试验证这一点；训练异常会写 FAILED 收据，并拒绝覆盖已有实验。
5. 修复 Adapter 初始化消耗随机数引起的对照漂移：采样前重设同一 seed。无 Adapter 与零 Adapter 在 150 / 225 帧输出逐字节相同；三组采样噪声 SHA 一致。官方150和原 V0.5 Temporal150也逐字节复现原有 native.npy。
6. 软条件覆盖率、直接输出约束比例分开。连续 Adapter 条件不是硬输出锁定。研究权重同时保留 music_qualified=false、full_motion_qualified=false；默认不能启用，实验必须显式给 research_allow_motion_only_adapter。

## 真实 300 步训练

568 个候选窗口中，上身48D支持 564，完整151D支持仍为 0。实际训练 527 窗口、7 个来源组；保留 37 窗口、1 个来源组 male_ribbon_sequence_2。优化300步，仅更新 Adapter；550 个训练样本使用非匀速相位增强，无不支持回退。音乐输入为零，其他103维仅作中性占位，**不是完整动作真值**，损失仅针对被隐藏的48D坐标。

固定协议用保留来源中均匀选取的8个窗口、固定噪声及 t=100/500/900 评价。验证用于检查点选择，因此不是独立盲测。

| 固定验证条件 | 隐藏48D MSE |
|---|---:|
| 零 Adapter | 0.03837597 |
| 训练后 + 来源条件 | 0.03174474 |
| 训练后 + 移除来源条件 | 0.03403359 |

相对零 Adapter 的 MSE 降低约 **17.28%**；来源移除后误差回升，说明本补全诊断对来源条件有依赖，不能推出完整动作、音乐同步或文化语义能力。仅一个保留来源组、8个评价窗口，无多 seed 统计推断。

## 生成、来源跟随与物理结果

固定同一真实 Jukebox 音频缓存和 seed=20261111。zero / probe 使用完全相同 Event Plan；none 与 zero 在相同自定义采样器中数值相同，表中合并为 zero。官方 long DDIM 与自定义采样器的细微数值差异不当作 Adapter 收益。

jerk 单位 m/s³，滑步 P95 单位 m/s，来源角误差为支持域内上身 SO(3) 平均弧度，上身活动为 rad/s。来源误差只衡量跟随源姿态，不代表音乐或文化语义正确。

| 案例 | jerk 峰值 | 滑步P95 | 来源角误差 | 上身活动均值 | 完整Native |
|---|---:|---:|---:|---:|---|
| official150 | 4738.18 | 0.6956 | 0.7401 | 1.6548 | 未通过 |
| temporal150 | 4766.24 | 0.6677 | 0.6351 | 1.8951 | 未通过 |
| zero150 | 4738.18 | 0.6956 | 0.7401 | 1.6548 | 未通过 |
| probe150 | 3244.15 | 0.4536 | 0.7345 | 1.4606 | 未通过 |
| zero225 | 4294.89 | 0.7319 | 0.8508 | 1.8817 | 未通过 |
| probe225 | 4002.50 | 0.4413 | 0.8211 | 1.3819 | 未通过 |

八例主生成（另含 none150 / none225）为 **0/8 Native 通过**；重复推理也未获得新的资格。FK误差均小于 1e-5 m，参数哈希前后一致。

探针的 jerk / 滑步下降伴随上身活动与整体速度下降，来源角误差只小幅改善，150帧误差仍高于 V0.5 Temporal。相同音乐节拍下速度极小值距离：150帧 zero 0.06250s → probe 0.06667s；225帧 0.04848s → 0.05152s，未改善。这是近节拍诊断而非音乐质量判决。不能凭更低 jerk 宣称方法整体更优或风格更强。

225帧仅用于跨窗工程诊断，虽未经150帧物理资格仍显式运行，以验证重叠接口；不作为质量升级。未继续新450/3601帧 Adapter 推理或追加调参。

## 复现与产物

以下输出目录必须不存在；命令需在已具备实际资产的服务器执行：

~~~bash
tmux new-session -d -s ddg-v06 'python scripts/v06_experiment.py --assets outputs/event_plan_01/prepare/assets.json --prior-root outputs/event_plan_01 --out outputs/v06_new --steps 300 > outputs/v06_new.log 2>&1; echo $? > outputs/v06_new.exit'
python scripts/verify_v06.py --root outputs/v06_new --replay
~~~

重复 --replay 也使用新目录，拒绝覆盖已有重放。只读复核可省略 --replay；服务器源资产引用需保持有效。

本地视频 outputs/v06_01/comparison_150.mp4（150帧/5秒）、comparison_225.mp4（225帧/7.5秒），带原音频，已核对帧数与画面。左为同噪声零 Adapter，右为真实训练48D探针。视频不替代 Native 验收。

SSH 使用进程内客户端，没有生成临时凭据脚本、askpass 或 key；没有删除既有SSH配置、实验资产或用户文件。
