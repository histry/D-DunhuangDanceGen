# 首轮敦煌舞生成实验：姿态命中与连接质量

单曲、单种子（20261111）。5 秒、15 秒和整曲共六条真实动作全部生成并完成 Native 审核，**0/6 通过原绝对物理阈值**。这项实验表明可以约束指定的上身关节，尚未证明可以生成自然、物理合格或经独立评价具有敦煌风格的完整舞蹈。

原先预设每个姿态控制 12–21 共十个关节。三个所选姿态均在左右腕（20、21）超出冻结 normalizer 的训练支持区间；三种时长均在采样前拒绝。后续独立实验仅控制 12–19 八个关节，使用原姿态、音乐、时刻、seed、预训练权重和物理阈值，不裁剪目标、不改动 normalizer。此变更不能视作十关节目标成功。

角误差在同一组目标姿态、三个目标时刻和八个目标关节上计算。单帧位移取每个锚点进入/离开两步中所有 SMPL24 关节的最大值。每条整曲 3601 帧，48 个重叠窗口。原阈值：滑足 P95 ≤ 0.18 m/s，最大关节 jerk ≤ 1620 m/s³；完整阈值及所有失败原因保存在逐例 physical.json。

三个时长中的锚点附近位移和全序列最大 jerk 均明显增加。姿态误差接近零是逐步硬约束的结果，不能作为去噪器自行学会风格的证据。两种采样器的重叠处理也不同，因此差异不全能单独归因于锚点。没有进行风格训练、人工自然性评分或多曲统计。

## 复核

- `reports/experiment_v1.json` 含动作 SHA256、采样提交、完整失败原因、单曲 seed、每个真实窗口边界、音乐速度极小值对齐和真实 FK 误差。
- `outputs/server_evidence` 是本地取回的证据；`experiment_v1` 保留原十关节拒绝，`supported_upper8` 保留较窄的成功采样、原 Native 拒绝及八关节匹配对照。逐例 Native 动作、FK、参数哈希和请求均可复核。未将数据集或动作上传到 GitHub。
- `outputs/comparison_15s.mp4` 是同一音乐、同步 30 FPS 的真实 Native FK 对照（非人体网格渲染）。
- 服务器保留原始归一化窗口和未拼接窗口。`scripts/summarize.py` 可在服务器 outputs 或本地 server_evidence 上重算汇总。汇总只把实际后续窗口的起点计为边界；早期逐例 evaluation.json 中额外列出的末半窗点不作为边界。
- 服务器八关节运行：首轮完成后，使用 `tmux new-session -d -s dunhuang-upper8 '/home/disk/lsm/conda_envs/dance-rag/bin/python scripts/run_supported_probe.py'`。独立输出目录拒绝覆盖。

下一项有针对性的验证是，在相同八关节、曲目和种子下对照提前若干帧渐进引导与当前硬约束，同时固定窗口共识方法。以目标误差、锚点邻域位移/jerk、滑足及 Native 完整审核共同判断，不放宽原阈值。
