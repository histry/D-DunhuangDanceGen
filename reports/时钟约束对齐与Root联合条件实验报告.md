# 时钟约束对齐与 Root 联合条件实验报告

代码、训练、真实生成、独立重放和来源核验均已完成，但本轮没有建立稳定的时间对齐或 Root 条件收益。新模块保持研究 Shadow，默认检索、原冻结 EDGE 和31项 Native 门限不变；没有增加独立 RootNet 或 Root 输出拼接。

对齐最终执行代码为 b28d779aeeba62d866645b079377cfb7799b0cfb；Root 条件执行代码为76d28b59b023d7d5f288d9be1d6363b066b3fccf；来源/依赖补充审计为34aa7ad121f8581f39c4c09436249c1f4ec1ca9c。报告随后提交，计算版本与报告版本分开记录。代码每次先发布 GitHub，再由服务器直接 pull，使用独立 tmux 会话执行。

详见[机器汇总](clock_root_summary.json)及[算法、标注边界与复现入口](../docs/clock_root_research.md)。

## 1. 实现了哪些机制

保留 SDMR 的50D音乐/74D动作双塔、128D局部Token和256D全局检索空间；原全局编码器及归一化冻结。新增双侧 NULL-dustbin、可学习拒配代价、对数域 Sinkhorn、真实时钟±0.5秒硬带宽、有效区域掩码及期望位置单调正则。NULL 没有固定20%目标，其质量分配也不是经标定的置信度。

C 在 B 的基础上增加停止梯度的软位置对比：同音乐/同编舞的其他舞者不会仅因身份不同而成为负例，跨例负样本只来自不同已知关联组。时钟带宽与单调正则不保证严格单调，因此始终检查违规数；OT对应矩阵不会替换 Planner 的原严格单调 Source→Music 映射。

A使用原Sync结构并从旧同步头初始化；B/C使用相同身份投影初始化，参数和初始化哈希完全相同。A/B参数量及既有同步头预训练历史不同，不能把A/B差异当成唯一因素的严格因果估计；B/C才是位置对比的同参数受控比较。全局检索始终使用原冻结编码器。

Root 部分新增37D来源描述：相对平移/速度、朝向与角速度、几何接触代理及观测掩码、来源移动变化候选时刻、进入/退出速度与朝向。它通过零初始化投影进入原 Event–Music Adapter，共享一个 EDGE 全身生成器，不直接覆盖 Root。真正静态接触置信度仍为0；未核实的 Root 也不会被编码成“真实静止”。225帧重叠条件一致性、未知存储隔离、哈希/时钟绑定、零分支旧输出同一性均有回归检查。

传统敦煌事件没有新增 Root 观测证明时，该分支明确缺失，不凭文件中的零值制造 Root 真值。代码已接通实际研究生成入口，但未提升正式资格。

## 2. 人口、软件与固定预算

对齐使用1480个Train窗和481个Val窗，分别来自713/223个录制、60/20个官方编舞、36/12个音乐身份和6/2个已知关联组。457个Test窗不做本轮新特征提取、模型选择或指标评价。沿用的原严格全量生成资产预检仍会读取文件做哈希/表示合法性核对，这与Test训练或效果评价分开记账。

Root跨录制任务使用1468个Train目标、既有固定8个Val任务；来源与目标是同官方编舞/音乐/时段的不同录制，不是假设姿态或Root轨迹逐点相同。Root责任诊断另覆盖1468个旧目标与42次保存生成执行。

每个A/B/C头固定800步、batch12、相同Train抽样日程、固定最终步，不以新Val重选权重。Root两组均从既有Cross Adapter已选400步权重热启动，增加零初始化Root投影后，再各训练400步，不能称为从零完整重训。Root完整/Root掩码消融使用相同初始化/参数量/批次/噪声，均362160参数；掩码组保留投影结构但条件输入为零。六次150帧生成使用同一固定种子、两个固定音乐窗，比较完整条件、移除Root条件及掩码训练组。

原始动作先在完整录制上解码为30Hz并计算身体旋转速度，再切出真实150帧halo与120帧音乐核心；错位为±8/±15帧非循环裁剪。真实配对源时钟不等于音乐重音与动作发力逐帧真值。没有独立发力标注，因此未额外用未经验证的峰值定义硬 D_beat 成本。

最终音频版本与冻结编码器旧缓存/真实查询统一为librosa0.11.0，SoXR0.5.0.post1、lazy_loader0.4、msgpack1.1.0均通过官方wheel SHA与隔离文件清单绑定；共享Python安装未修改。提取前和实际服务均检查音频版本。

旧源码暴露的组合音频/动作CONTRACT曾被整份复制进早期元数据，但本轮实际motion74是解码后native30的完整录制导数，不是旧native60先导数再采样分支；已修正组合合同并保留勘误。新数据与服务端执行表示一致，但相对冻结旧编码器的预训练运动表示仍可能存在分布差异，本轮不代表联合重训编码器的性能上限。

已核对旧SDMR训练档案：当前Train的36个音频/713个原始动作对应旧Train，当前Val的12个音频/223个原始动作对应旧Val，没有发现这些已知来源落入旧Train。前32个共享非Test音频缓存窗掩码一致、最大绝对差5.7220459e-6，非逐位完全相同；不能将32窗检查扩展为所有来源的数值证明。Val历史上已用于开发/选权，未知EDGE预训练暴露也未完全证明，仍不属于新盲测。

## 3. 最终对齐结果

下表为481个Val查询、按223个录制均衡的正确时钟相对四种真实错位的胜率。区间为录制组重采样的诊断结果；最高关联组只有2个，不能宣称统计独立性或区间覆盖率已成立。

| 方法 | 正确时间胜率 | 录制组重采样区间 | 同音乐源时段 Recall@1 |
| --- | ---: | --- | ---: |
| A：原Sync结构 | 50.30% | [46.57%, 53.52%] | 44.91% |
| B：时钟NULL-OT | 47.57% | [44.75%, 51.35%] | 56.76% |
| C：B+位置对比 | 49.70% | [46.98%, 53.05%] | 49.06% |

能量基线的同一时间胜率为39.65%。不同任务的指标不能混用：同音乐时段检索变化，不等于正确时间相对错位辨别已经成立。C没有稳定超过A，三个时间区间均跨越50%，不授予正式检索资格。

B的平均匹配覆盖为50.64%，每窗期望位置逆序数均值6.235；边际误差最大1.79e-07。

C的平均匹配覆盖为51.89%，每窗期望位置逆序数均值1.031；边际误差最大1.19e-07。

C的覆盖不是全部拒配，但这不证明NULL具有正确语义。所报OT时钟一致性偏移受时间带宽先验直接约束，不是独立标注的动作发力定位误差。原偶/奇帧下采样敏感性与抗混叠诊断已保留；特征变化减小不等于保留了语义峰值，所以没有自动替换池化，也没有追加正交EMD/第二套Transformer寻优。

实际服务已对保存的非配对A65音乐及两个敦煌事件执行新C打分。输入仅为音乐特征、候选来源与既有时间映射，没有目标动作配对真值。原计划语义身份/选中事件/时间映射未变，transport_can_route=false。这是服务接口与真实推理检查，不是非配对检索正确率或新整曲生成效果。

## 4. Root责任与联合条件

Root责任分解使用向量恒等式 J_world=J_root_translation+J_root_relative，平方量另保留有符号交叉项，不能把标量峰值相加成“因果贡献百分比”。Root-relative仍含根朝向变化，Root-frame是另一个坐标诊断。

1468个源目标的窗口Jerk峰值中位数分别为：世界2588.87、Root平移542.47、Root-relative2669.22、Root-frame3718.73 m/s³。移除Root平移并未让其余运动自动平滑，不能据此认定Root是唯一瓶颈。

42次保存生成分别进行固定平移、固定Root刚体变换、固定局部身体旋转三种反事实，共126个诊断副本。它们不是修复候选，也未宣称物理可执行，原动作与判决未改写。

完整Root条件与掩码组的整体验证MSE分别为0.0113726440和0.0113727677；Root通道MSE分别约0.00205418684和0.00205424204。移除Root条件变化很小，移除参考内容但保留既有时钟/音乐后甚至得到更低误差，不能把整体去噪误差下降当作可信原语/Root控制收益。

六例Native仍0/6，Root轨迹差异极小且未呈稳定收益。不放宽门限、不更换最有利地面、不粘贴Root输出，也不追加RootNet/SQP。本轮没有证明独立Root网络的必要性，也没有排除其他训练预算/表示下Root条件可能有效。两个音乐窗、单种子、150帧示范不能外推到225/450帧或整曲质量。

## 6. 研究边界与后续准入

本轮取得的是完整、可训练、可推理、可复验的研究接口和受控结果，尚不是已成立的机制创新或最佳模型质量结论。当前Train/Val已知身份隔离不等于整个预训练模型的新盲测；配对源时钟不等于独立动作发力标签；Root反事实不等于物理修复；旧Native通过率不等于专家自然性。

继续保留原正式路径。若后续改进，应单独注册新的表示/编码器训练与来源验证，补足可靠事件对应/接触与专家证据，再验证检索变化是否转化为原语跟随和生成收益。不能在当前Val上反复重选结构、阈值或权重后再声称留出泛化。

方法借鉴[VTaMo论文](https://arxiv.org/html/2607.09126v1)及[核对版本的官方OT源码](https://github.com/junyi2005/vtamo/blob/a674902d8eeff9e7e2dc68c727418936542ba5a0/vtamo/ot_sinkhorn.py)，没有复制其手语文本主干、T5或视觉重排，也不声称完成其论文复现。物理指标沿用[既有Native审计边界](Native物理评价可靠性报告.md)：PFC是已绑定定义，PhysDiff为声明协议差异的附录重实现，均不自动授予人类感知或动力学资格。
