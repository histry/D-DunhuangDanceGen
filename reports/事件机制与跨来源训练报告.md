# 事件信息流、跨来源条件训练与 Native 目标审计

本轮完成原生事件条件、跨录制监督、同参数量融合对照及真实服务器实验。工程链路可训练、可生成、可独立重放；事件执行控制和完整物理质量仍未合格。默认生成路径保持 Temporal V0.5，研究权重没有替换默认模型。

## 版本与数据

基线诊断提交 `0e38bc3`；两模型训练与28次新生成固定在 `7a1d368`；独立重放为 `3fbe5d0`；Train目标审计与官方PFC复算为 `26bb74e`。先发布GitHub，再同步服务器执行。所有阶段使用tmux、独立新目录、持久日志和退出回执；全部exit0。

复用已校准的2,418窗真实配对清单和127份去重Layer66 Jukebox。来源台账仍为1,166条基础舞准入、197条高级舞身份未解而排除。冻结角色、Scaler与EDGE不变。跨来源任务只保留不同录制/不同原始字节，且官方基础编舞、原音乐字节、起始帧、offset、FPS与时长完全相同的关联：Train1,468窗、Val446窗；Test不参与拟合、源条件或选权。共享编舞不是逐姿态相同标注。

151D目标为147D拟合参数加4D派生Contact；源条件只读取其独立来源的可信上身局部旋转。两者不混作同一个真值合同。

## 实现

1. `source_pairs.py`：显式保存source/target UID和录制关系，拒绝跨角色、自来源、错音乐/时钟及虚构的pose-exact关系。
2. `event_geometry.py`：8个局部关节的绝对、首个可见姿态相对、相邻SO(3)列表示，加mask8与phase1，共153D。未知存储先隔离，不使用目标Scaler裁剪参考。
3. `event_music_adapter.py`：153→128事件编码、512→128音乐投影、单层融合注意力及零初始化512D残差。Cross使用音乐query；Additive使用事件自注意力加音乐投影。两者参数量均357,424，初始权重哈希完全相同。
4. `event_transfer.py`：真正不同录制的源事件与完整目标分别输入；全151D目标MSE +0.1目标速度误差 +0.02 SO(3)弦距离 +0.05可见来源旋转重建。后者是来源信息保持目标，不是假造的全身监督。
5. 现有单一EDGE生成入口接通原生来源几何，须显式设置两个research标志。真实ChangE参考通过该路径执行，无源姿态粘贴、无第二生成器、无新Scaler。
6. 加入层间身份探针、相位/Mask/音乐/来源干预、匹配噪声因子实验、同四帧Jerk追踪、只读神经/Native重放、预训练名单及训练目标合同审计。

入口及复现命令见 [运行合同](../docs/event_mechanism.md)；研究配置见 [原生条件配置](../configs/native_event_adapter.example.json)。

## 信息是否丢失

8个固定历史Val事件、3个可见性视图。所有事件共用同一音乐和同一带噪状态，避免从目标状态识别来源。固定ridge探针在两视图拟合、第三视图检查：旧paired300模型及两种新模型的Adapter128/512与8层decoder均达到8/8闭集区分；纯音乐层为机会水平1/8。

这只证明该小闭集内的信息仍可解码，不是新来源准确率、文化语义识别或稳健性证明。旧512D事件描述有效秩约1.30，新Cross约1.16；到decoder7约1.06。不能仅凭高token相似度宣称完全塌缩，也不能把可解码等同于可执行。

各模型另保存384次带噪目标干预观测：8窗×2种子×3时间步×8控制。它们属于去噪补全诊断，不是自由生成。详见 [层间统计](event_information_flow.csv)。

## 同参数量训练结果

两种模型均训练1,200步，seed20261115、batch2、AdamW1e-4、梯度裁剪1。每100步在固定8个跨录制Val对上按完整151D MSE选权，两者均选第400步。

| 固定Val控制 | Cross MSE | Additive MSE |
|---|---:|---:|
| 零Adapter | 0.0118528709233 | 0.0118528709233 |
| 正确来源 | 0.0112534551493 | 0.0112536077286 |
| 移除来源 | 0.0112459904000 | 0.0112465535155 |
| 错误来源 | 0.0112546215945 | 0.0112547851798 |
| 反转Phase | 0.0112534634366 | 0.0112536145898 |
| 替换音乐 | 0.0193414024567 | 0.0193409017666 |
| 循环错位音乐负例 | 0.0158328270845 | 0.0158309870142 |

正确来源的MSE相对零Adapter约下降5.06%，但来源移除/替换几乎不改变结果，Cross与Additive差异约1.53e-7，没有证明联合注意力收益或可靠事件控制。错位音乐仅作诊断负例，未用于训练或冒充真实配对。

Cross输出归一化速度RMS约0.05325，零Adapter约0.05318，目标约0.08276。此均值未表现为相对零Adapter进一步降活动量，但二者均低于真实目标；不能据一个RMS排除局部低活动偏置。

新进程把音乐干预同时施加到冻结EDGE和带Adapter模型：换曲MSE惩罚分别约0.008315/0.008088，错位惩罚约0.006989/0.004579。音乐敏感性已存在于冻结主干，不能算作新Adapter学会音乐演绎的证据。完整数值见 [验证表](event_transfer_validation.csv)。

## 实际执行与物理结果

旧paired300诊断12次；Cross和Additive各12次AIST因子生成及2次真实ChangE/A65条件生成，共40次执行、32个不同动作哈希。重复零Adapter控制不计为独立样本。全部50步DDIM、相同音乐/噪声配对、无事后姿态写入。

Native为0/40，其中本轮两种新模型0/28。四组事件交换的SO(3)自身/他者姿态偏好差均接近零，新模型没有稳定正向偏好。不能把输出RMS变化当成跟随来源。见 [姿态偏好](event_pose_preference.csv)。

36次AIST因子执行中18次在装配前已超过同一Native最大Jerk门限。全部同四帧模板中，装配/FK往返后的同模板Jerk差最大约0.103m/s³，原窗口峰值可达约19,405m/s³。新模型反向步索引0/24/49的Jerk也已保存并独立按Native FK重算。此证据限150帧单窗，不能证明225帧或整曲拼接已解决。

[官方EDGE PFC源码](https://github.com/Stanford-TML/EDGE/blob/17c3428669ed6733edd9d8c66f7dc62060b8e46d/eval/eval_pfc.py)对40个保存FK逐例复算，与项目实现完全一致：

| 相同AIST非零Adapter8次执行 | PFC均值 |
|---|---:|
| 旧paired300诊断 | 0.379635 |
| Cross | 0.246166 |
| Additive | 0.245535 |

旧paired300的数据任务/参数/步数不同，只作历史诊断参照；严格融合消融是Cross与Additive。ChangE两次执行的均值分别约1.153095/1.153055。PFC采用官方位移乘积×1e4定义，不是m/s、Native门限或论文排行榜；PFC下降也没有带来Native通过。详见 [PFC分组](event_pfc_summary.csv)。

## 目标与验收合同的失配

额外只读审计全部1,468个跨录制Train目标：40窗满足当前Native合同，1,428窗未满足；最大Jerk中位数约2,588.87m/s³。固定8个Val目标另有1个通过。Train审计没有加载Val/Test目标动作、没有过滤数据、没有重选权重或再次训练。

这是拟合目标对本项目验收合同的成员性结果，不是对真实视频、数据集合法性或来源事件可用性的否定。窗口重叠也不构成独立样本。因此不能把数值支持域与完整配对预检通过，升级成物理监督质量合格；仅拟合所有目标的MSE不直接优化Native可行性。

## 曝光、复核与交付

[固定EDGE训练分割脚本](https://github.com/Stanford-TML/EDGE/blob/17c3428669ed6733edd9d8c66f7dc62060b8e46d/data/filter_split_data.py)使用的名单中，当前完整配对清单的Val来源有152条属于官方Train名单、4条属于官方Test名单，67条不在该固定配方的有效Train/Test集合中。实际下载检查点的完整训练血缘未获证；不在名单不等于未曝光。历史Val不作新盲测或未知敦煌泛化结论。

966个归档实验输出文件、169,143,258字节已在两端保留，并逐文件SHA256核验。完整逐窗清单、模型、数据数组、日志和原服务器路径回执位于忽略输出目录；GitHub发布实现与去除来源身份/服务器路径的汇总。临时传输ZIP已从两端删除，SSH仅用内存会话，未创建临时SSH辅助文件。
